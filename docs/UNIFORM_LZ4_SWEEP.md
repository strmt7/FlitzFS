# Experimental finite uniform compression sweep

The separate `--driver-uniform-lz4-sweep-adapter` processes one admitted immutable request as serial device quanta while keeping the authenticated runtime and kernel modules loaded. It creates no persistent worker, service, idle loop or additional process. The ordinary single-window and profiling commands retain their contracts.

## Plan, ownership and failure

`plan_uniform_lz4_sweep` performs an allocation-free binary search for the largest quantum admitted by the supplied maximum chunk count and complete device-byte grant. The chunk width comes from the owned whole request. The plan includes exact whole-frame limits, quantum count, number of windows and actual peak slab bytes. Representation limits remain distinct from resource authority.

`compute_uniform_lz4_sweep` validates the plan against the immutable whole source before allocation or callback execution. Missing independent CPU decoding refuses before compute. It reserves a single dense result within the exact complete-reply bound and owns one prepared quantum at a time. Every callback result must independently decode to that quantum's source before concatenation. The complete combined result is checked again before ordinary reply encoding.

The trusted caller must admit the WHOLE input, dense worst-case result, one prepared quantum, scratch and transport copies against current host/process headroom before entry. A small device quantum does not authorize an unbounded host request. The worker retains sized-transport admission, process/aggregate hard jobs and fresh host/GPU re-admission. Quanta are serial. The new [reusable compute scope](UNIFORM_LZ4_REUSE.md) retains one verified setup, stream and slab for the finite operation. Each quantum synchronizes, validates all active/unused bytes on CPU and repeats fresh resource admission before another begins. Complete stream/slab retirement remains mandatory before the combined result escapes. This scope passed source-specific core/SDK and one bounded aligned hardware case at `d33efd6`; see [the executed reuse evidence](evidence/uniform-reuse-d33efd6.json).

Failure in any quantum terminates the operation and destroys its private accumulated candidate. No partial reply, retry, replacement worker or native publication occurs. Only after all quanta, independent verification and successful module retirement may the child publish one unchanged version-2 reply. The parent still requires successful confirmed exact child/supervisor exit before copying, and independently checks every chunk against its retained source. CPU result selection in the asynchronous controller remains independent of worker cleanup; this new explicit diagnostic is synchronous and does not establish that controller integration.

## Explicit diagnostic and qualification

The optional hosted SDK fixture adds `--uniform-sweep-native-cpu-fixture` and `--gpu-uniform-sweep-native-once`. The synthetic group uses the current native write limit (1 MiB, sixteen 64-KiB extents), rather than imposing a new product group ceiling. The hardware experiment retains the previously observed two-chunk quantum (328,288 explicit device bytes), eight serial windows, the existing five-second worker job observation, 128-MiB child/256-MiB aggregate jobs, low priority and twenty-percent CPU cap. These are experiment budgets, not product defaults.

The authoritative live/checkpoint image remains two 2-MiB locked buffers. Current/prior independent CPU recovery and exact candidate storage are required for every matching data object, whether repeated extents share objects or occupy separate records. Old one/two-extent controls remain. The sweep diagnostic records complete exchange time and actual peak slab bytes; it does not emit a phase profile, and zero phase fields must not be interpreted as zero kernel cost.

Portable and SDK CPU tests cover seventeen chunks with a partial final window, exact concatenation, device-peak boundaries, malformed plans, absent decoding, actual typed-compute reuse and terminal second-window failure with no partial result. Hosted admission checks require twenty confirmed child exits, including sweep grant/frame refusals before AMD loading. New publishing-source qualification is pending. Owner execution additionally requires the complete matching core matrix, SDK qualification, reviewed artifacts/source, fresh runtime/adapter/topology/headroom and verified retirement. No normal callback launches this mode.

## Executed qualification and retained owner failure

Source `847423fb996bef964d1da1d49a1f6376a07d5333` passed all thirteen core jobs (run 43608595532), 152 native Windows groups, both Linux 131-test configurations, Windows raw and sanitizers. Full SDK run 43608595922 passed 1,477 checks across 42 uniform-compute CPU scenarios (5 successes, 37 refusals), the raw refusal and 126 admission checks with 20 confirmed exits. The larger CPU native fixture stored its exact advice, recovered current/prior bytes independently and released all 4 MiB of locks.

The separately admitted owner trial then FAILED. Its worker exited with native code `0xc0000409`; peak commit was 133,992,448 bytes (127.785 MiB), close to the 128 MiB child job limit. No crash subcode, stack or allocator evidence was collected. The proximity is not proof that the memory limit caused the exit. No GPU payload was accepted and this source is not qualified for another hardware sweep.

CPU fallback published all 1,048,576 source bytes and independently recovered current/prior data. The image occupied 1,114,112 bytes with 135,561 active payload bytes. Exchange time was 2,861,650,000 ns, not a successful GPU throughput result. All 4,194,304 locked bytes returned to zero, working-set limits restored, exact transport retirement completed and staged input/runtime hashes remained unchanged. Postflight found no FlitzFS process and the GPU reported healthy with unchanged driver version.

[Complete source, artifacts, raw outcomes and containment evidence](evidence/uniform-sweep-847423f-failure.json) is retained. Do not repeat the unchanged trial or increase its job cap to obscure the failure. Green CPU/SDK checks did not predict this hardware outcome.

## Next mechanism, not a diagnosed fix

The current sweep repeats device initialization/properties/topology and stream/slab creation per quantum. The next implementation should retain one bounded operation's verified device setup and reusable stream/slab, synchronize and CPU-verify each quantum, repeat fresh memory admission, protect the unused slab tail for shorter quanta, and retire the resources before any combined result returns. The [reusable compute candidate](UNIFORM_LZ4_REUSE.md) now implements that revised lifetime and adds SDK fault/ownership tests. Its core/SDK qualification and one bounded aligned hardware case passed at `d33efd6`. This does not prove the abnormal exit's cause or qualify other workloads. No normal callback route or new owner trial follows before its separate gates pass.
